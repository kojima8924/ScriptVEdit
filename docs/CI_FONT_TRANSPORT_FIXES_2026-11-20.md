  板つきの札・自動中央寄せ・odometer の重ね合わせは維持する。

  フォントの高さに由来する y 座標だけを更新した。尺・コマ数・フィルタ順・エンコード設定は同じ。
  Pillow 10.4 と 13 の両方で、このスナップショットと配置テストの成功を確認した。

## fly_to の輸送計算

### 原因と変更

旧実装は単精度の行列積を BLAS に任せ、射影の同値順位にも不安定ソートを使っていた。
同じ入力に対して積和を明示的な配列演算へ置き換えるだけで、代表場面のキャンバスが
`330x162` と `330x150` に分かれ、中間の粒の軌跡も変わった。Pillow 10.4 と 13、
NumPy 2.0 と 2.3 で旧失敗が再現し、単なる画像のラスタライズ変更ではなかった。

`_sliced_ot_flow()` の計算だけを次のように変更した。

1. 座標と射影を float64 にする。
2. 2 項の射影を明示し、方向ごとの加算を固定した順で行う。
3. 射影が同値の粒は入力順を保つ。

方向数 64・反復数 40・標本の取り方・乱数 seed・Hilbert 対応・道すじ・色・尺の仕様は同じ。
三角関数の最終ビットまで全 OS で一致すると主張するものではなく、BLAS と順位の不安定性を
取り除く修正である。Linux と Windows の CI による実際の金型検証は引き続き必要になる。

### 検証と金型

独立した Python スカラー参照計算を追加した。36 粒、重複する座標あり／なし、方向数
1／7／64 の 6 条件で、最大誤差 `2e-10` 未満を要求する。
重複座標を含む条件では旧コードと参照のずれが 0.20〜1.45 px、修正後はローカルで 0 だった。
既存のハンガリアン法との移動量比較、最初と最後の画素完全一致、キャンバス内への収まり、
色・アルファ、キャッシュ、実レンダ、dry_run の一致もそのまま実行する。

描画が変わるため `_FLIGHT_VER` を 2 から 3 へ上げた。金型 3 枚を更新前後で目視し、
赤い輪が紫の粒として青い縦棒へ飛ぶ構図・色・透明な周囲が保たれ、粒の軌跡が変わることを
確認してから PNG／JSON を更新した。新しい金型は `330x162`。
`test130` は版 2 の保存コマンドと完全一致することを先に確かめ、版 3 のキャッシュハッシュ
だけを更新した。`test131` は既存のハッシュ正規化だけで成功する。

金型の閾値は blur=1、color=1、alpha=0.01、余白差 8 px を維持する。
以前の雑音テストは Hilbert 対応の前に 0.01 px の揺らぎを加えていたが、順位の離散変化で
実際に軌跡が変わる場合がある。修正後の代表場面では blur 差が 3.56 となったため、これを
許容するように閾値を緩めてはいない。float64 の 64 ULP の丸め雑音は通し、0.01 px の
揺らぎは軌跡の変更として検出する。色の暗化・アルファの二重掛け・止まる幅・粒の半径・
出発の揺らぎの 5 種類の変更も従来どおり検出する。

### 計算時間

ローカルの 12,000 粒の輸送計算だけを同一入力で単発測定すると、旧版 0.765 秒、
新版 2.627 秒だった。前処理は重くなるが、生成済み動画は従来どおりキャッシュされる。
元の Windows 実測は旧 float32 実装の値と明記し、現行版の性能値として扱わない。
